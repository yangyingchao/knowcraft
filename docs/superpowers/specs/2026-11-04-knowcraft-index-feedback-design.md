# knowcraft 索引进度与文件状态反馈设计

- 日期：2026-11-04
- 状态：设计完成，直接进入实现
- 关联设计：`docs/superpowers/specs/2026-11-03-knowcraft-search-dispatch-design.md`（5.2 运行期更新）
- 关联代码：`crates/knowcraft/src/knowledge.rs`、`crates/knowcraft/src/ui/window/knowledge_dispatch.rs`

## 1. 目标

GUI 导入文件后，由本进程主动建立全文索引，并向用户提供两级反馈：

1. 逐文件状态徽标：排队、索引中、已索引、失败。
2. 全局进度：发起导入或重新索引的窗口在右下角进度坞显示「正在索引 3/12」，
   结束后显示完成或失败摘要。

## 2. 现状

| 能力 | 现状 |
| --- | --- |
| 导入 | GUI 目录导入走 `knowledge::import_directory`，只拷贝并登记为 `pending`，返回后不索引 |
| 索引触发 | 仅启动时 `spawn_warm_index()` 后台补索引；外部 watcher 未部署 |
| 索引状态 | DB `documents.index_status` 有 `pending/indexed/error`，但 UI 从不读取 |
| 文件行 | 文件管理器目录视图，不关联 `Document`，无任何索引状态展示 |
| 失败处理 | 仅写 `error`，无提示、无重试入口 |

因此导入后索引是否在跑、是否完成、是否失败，界面完全没有信息。

## 3. 设计决策

| 决策项 | 结论 |
| --- | --- |
| 索引写者 | GUI 为唯一写者；外部 watcher 未部署，不并发写 |
| 并发模型 | 单 worker 串行索引，避免并发写 tantivy |
| 触发时机 | GUI 导入完成后自动入队；右键「重新索引」单文件入队；启动 `warm_index` 保留但静默 |
| 进度范围 | 仅 GUI 导入 / 右键触发的索引显示进度；启动补索引不显示 |
| 进度位置 | 发起操作的窗口右下角进度坞 |
| 逐文件状态 | 行内小状态图标 + tooltip |
| 状态来源 | DB `index_status`；「索引中」为 UI 内存态，不新增 schema 值 |
| 覆盖范围 | Inbox/Library/Notes/Captures；回收站不显示 |
| 失败处理 | 红徽标 + 右键重试；不做会话内自动重试，启动 `warm_index` 兜底 |
| 错误原因 | 不显示具体错误文本（无 schema 字段） |

## 4. 索引队列

### 4.1 位置

在 GUI `knowledge` 层新增索引队列与进度广播，不改 core `Index` 接口。

### 4.2 结构

- 进程级单例队列：`std::sync::mpsc` 发送任务，单个后台线程消费。
- 任务单元为待索引文档路径与其 `Document`。
- 消费者对每篇调用 `Index::index_documents`，成功置 `indexed`，失败置 `error`。
- 队列串行执行，与启动 `warm_index` 通过同一把索引写锁或同一队列串行化，
  禁止两个线程同时写 tantivy。

### 4.3 入队

- 导入目录完成后，收集本次新登记且 `index_status != indexed` 的文档，整批入队。
- 右键「重新索引」把该路径对应文档入队；若尚未登记，先按所在文件夹登记。
- 重复入队按路径去重，已在队列中的路径不重复添加。

## 5. 进度通信

- worker 在线程内产生进度事件：`Queued(total)`、`Started(path)`、`Finished(path, ok)`、`Done { ok, failed }`。
- 事件通过 `glib::MainContext::invoke` 或现有 `glib::timeout_add_local` 轮询模式投递回主线程，
  模式与 `knowledge_dispatch::poll_result` 一致。
- 主线程收到事件后：
  - 更新进度坞文本与计数。
  - 标记当前目录为待刷新，刷新受影响目录的文件行徽标。
- 进度事件只发给发起操作的窗口；索引本身仍为进程级任务。

## 6. UI

### 6.1 文件行徽标

- 文件行在图标区域叠加或旁边显示一个状态点：
  - 灰：`pending` 且未在处理（排队）。
  - 蓝色或旋转：当前正在索引（UI 内存态）。
  - 绿：`indexed`。
  - 红：`error`。
- tooltip 文案：「排队中」「索引中」「已索引」「索引失败」。
- 回收站目录不显示徽标；非知识库目录不显示。
- 状态来自当前目录可见文件的批量查询：
  按目录路径前缀查 `Store`，建立 `path -> index_status` 映射；「索引中」集合由进度事件维护。

### 6.2 进度坞

- 复用窗口 overlay 的进度坞行，定位右下角，与文件操作进度统一堆叠。
- 进行中：「正在索引 3/12」。
- 结束：全部成功「索引完成 12 个」；有失败「索引完成 10 个，失败 2 个」。
- 结束后短暂保留再消失；显示在发起导入 / 右键操作的窗口。

### 6.3 右键「重新索引」

- 文件项右键菜单新增「重新索引」，所有知识库内文件可见（幂等）。
- 触发后入队并显示进度坞。

## 7. 数据流

```
导入目录
  └─ 后台线程 import_directory → 返回 ImportReport
       └─ 收集新登记非 indexed 文档 → 索引队列
            └─ 单 worker 串行 index_documents
                 ├─ 进度事件 → 主线程 → 进度坞 + 刷新徽标
                 └─ store.set_index_status(indexed|error)

右键重新索引
  └─ 当前路径 → 必要时登记 → 索引队列（同上）
```

## 8. 错误处理

| 场景 | 处理 |
| --- | --- |
| 知识库不可用 | 不显示徽标；导入沿用现有错误提示 |
| 单文件索引失败 | 置 `error`，红徽标；继续处理队列其余文件 |
| 队列去重 | 同路径已在队列中则跳过 |
| 窗口关闭 | worker 继续执行，事件丢弃不影响索引 |
| 启动补索引与导入队列重叠 | 通过同一写锁串行，避免并发写 |

## 9. i18n

新增文案同步 `data/locales/zh-CN.json` 与 `en.json`（含 `messages/` 下对应文件）：

- 「排队中」「索引中」「已索引」「索引失败」
- 「正在索引 %{done}/%{total}」
- 「索引完成 %{count} 个」「索引完成 %{ok} 个，失败 %{failed} 个」
- 「重新索引」

## 10. 测试

### 10.1 core / knowledge

- 队列串行：批量入队后全部置 `indexed`，`Index::search` 能命中。
- 单文件失败置 `error`，不影响后续任务。
- 重复入队去重。

### 10.2 GUI

- 徽标映射：`pending/indexing/indexed/error` 对应四种状态。
- 进度坞文案随事件更新，结束时显示完成/失败摘要。
- 右键「重新索引」对知识库内文件可见并触发入队。

## 11. 明确不做

- 外部文件系统监听与自动索引。
- 会话内自动重试。
- 索引失败原因文本（需要新增 schema 字段）。
- 索引任务取消。
- 启动补索引的进度展示。

## 12. 风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 大文件索引耗时 | 单篇 PDF 提取与写入可能数秒到数十秒 | 进度坞持续显示；worker 不阻塞 UI |
| 徽标查询开销 | 每次目录刷新查询 DB | 按当前目录前缀批量查询，不逐文件往返 |
| 与 warm_index 竞争 | 两者都写 tantivy | 统一写锁或统一队列串行 |
| 状态短暂不一致 | DB 更新与 UI 刷新有延迟 | 进度事件驱动刷新，完成后以 DB 为准 |
