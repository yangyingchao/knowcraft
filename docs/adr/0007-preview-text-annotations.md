# ADR 0007：预览文本标注只入库，不写源文件

- 状态：已接受
- 日期：2026-11-07
- 关联设计：`docs/superpowers/specs/2026-11-07-preview-text-annotations-design.md`

## 背景

PDF 预览已支持注释写回。非 PDF 的渲染预览与源码预览只有一个只读控件，
选中文字后无法留下高亮、下划线、删除线或附注。用户需要在预览里编辑标注，
但不希望改动 Markdown、纯文本等源文件。

## 决策

1. **文本标注只写数据库。** 复用现有 `annotations` 表，新增 `view`、
   `range_start`、`range_end` 三列；`view` 为空串表示 PDF，`rendered` 与 `source`
   表示预览文本标注。PDF 仍按 ADR 0004 写回文件。
2. **锚点绑定创建视图。** `rendered` 与 `source` 两套集合互不共享；切换视图只读取
   当前视图的集合。
3. **偏移口径唯一。** 以 `SelectionSpace` 的规范文本为准：每个 unit 贡献其复制文本，
   表格与媒体贡献单个 `U+FFFC` 占位符。PDF 以外的标注范围全部使用字符偏移，
   不保存字节偏移。
4. **不做自动重定位。** 加载时用当前规范文本比对 `selection`；不一致或越界的标注
   标记为失效，不绘制、不写回、不自动修复，只提供批量删除入口。
5. **写操作后台执行。** 创建、改附注、改色、改范围、删除与批量删除都经
   `AnnotationController` 转入后台任务，任务内先取 `index_guard`，再调用
   `TextAnnotations`，完成后回主线程刷新界面。
6. **索引按附注文字重建。** `Indexer` 已把非空附注拼入正文；新增或编辑附注、
   删除带附注的标注触发重建，改色与改范围不触发。重建失败时保留旧索引。
7. **交互能力按视图裁剪。** PDF 与文本共用抽取后的工具条与菜单；PDF 不支持改色与
   调整范围。

## 后果

- 源文件保持只读，标注随数据库备份与迁移；删除源文件不会删除标注，文档进入回收站时
  标注仍保留。
- 源文件被外部修改后，旧锚点按原文校验失效，用户需要重新标注。
- 预览截断到 1 MB 时，超出已载入文本的标注会被判为失效。
- 表格与媒体单元不提供标注入口，规范文本中的占位符仅用于保持全局偏移稳定。

## 替代方案

- **写回源文件**：Markdown 语法与纯文本编码差异大，重写会改变文件内容与校验和，
  与只读预览定位冲突。
- **按行号或字节偏移存锚点**：文件编辑后更容易漂移，且无法统一渲染视图与源码视图。
- **新建独立标注表**：与既有 PDF 注释的列表、菜单、索引路径重复，维护成本更高。
