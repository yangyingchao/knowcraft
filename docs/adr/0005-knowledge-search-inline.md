# ADR 0005：知识库搜索内联到面板过滤栏

- 日期：2026-11-07
- 状态：已采纳
- 关联设计：`docs/superpowers/specs/2026-11-07-knowledge-search-inline-design.md`
- 取代：`docs/superpowers/specs/2026-11-03-knowcraft-search-dispatch-design.md` 中关于全局搜索面板的部分

## 背景

原实现中，`Ctrl+K` 打开中央搜索面板，按「文件名 / 标签 / 文档内容」三段展示结果；
每列、每个面板另有独立的过滤栏，展开后在该面板内筛选或递归搜索。两者在输入方式、
结果呈现、键盘导航与状态管理上完全独立，用户需要在两套交互之间切换，且搜索面板无法复用
面板已有的结果列表、选择保持、缩略图、重命名跟随等机制。

## 决策

1. 知识库搜索并入面板过滤栏。列头漏斗之后新增放大镜开关，两者共用同一条输入行与同一次查询防抖；
   两个开关互斥，由 `FilterModeController` 统一持有 `(open, source)` 状态。
2. 搜索来源作为参数：`QuerySource::Files` 查询当前面板目录，`QuerySource::Knowledge` 查询知识库。
   文件过滤、递归搜索、知识库搜索共用同一套结果列表与键盘导航。
3. 知识库结果合并为一个扁平列表，顺序为文件名命中、标签命中、文档内容命中；同名路径以文件名行为准，
   三路上限分别为 100、10、20。
4. 结果行使用 `ResultRow::{File, Content, Tag}`。文档内容命中不包装成 `SearchItem`：
   `SearchItem` 的 `search_path`、`depth` 与评分字段只对文件系统遍历结果有意义，复用会扩散内部契约。
5. 行身份使用 `RowId::{Path, Tag}`。文件与内容行共享路径身份；标签行独立身份。
   选择保持、重命名跟随、存在性清理只作用于路径行。
6. 标签行不参与拖拽、剪贴板、重命名、缩略图与索引徽标。激活标签行把输入替换为 `tags:<name>`，
   以知识库模式重跑。
7. 目录命中关闭搜索并导航；文件与内容命中打开后保留结果。此行为与过滤栏的目录激活一致。
8. 中央浮层只保留「跳转文件夹」（`Ctrl+Shift+K`）。窗口 header 的搜索按钮移除，
   `Ctrl+K` 聚焦当前面板的知识库搜索输入行。

## 后果

- 搜索与过滤共享一套状态机、结果列表与键盘路径，减少重复实现与行为漂移。
- 列视图与列表/图标视图各自保留结果适配器（`ResultLists` 与 `ResultCollection`），
  二者消费同一份 `Vec<ResultRow>`，合并、去重与排序只在共享层实现一次。
- 标签与内容行的引入提高了结果消费者的复杂度：所有文件向路径必须显式跳过无路径行。
  新增结果消费者时需要检查 `ResultRow::path()` 的返回值。
- 搜索状态（来源与文本）进入面板过滤状态的持久化结构，页面刷新、视图切换与标签页切换后
  仍保持原来源。
- 原全局搜索面板的覆盖范围提示、搜索 provider 与标签模式被删除，相关 QA 场景随交互变更调整。
